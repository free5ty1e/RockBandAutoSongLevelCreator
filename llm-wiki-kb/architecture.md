# Architecture & Pipeline

AutoRB is a Python CLI tool that automates the creation of Rock Band 3 CON (STFS) files from raw audio and lyrics.

## The Pipeline
1. **Stem Separation:** Meta's `demucs` separates the source audio into `drums.wav`, `bass.wav`, `vocals.wav`, and `other.wav`.
2. **Tempo & Beat Mapping:** `librosa` analyzes the audio to generate a continuous BPM map and measure grid.
3. **Vocal Alignment (The LRC Upgrade):** 
   - Accepts Standard LRC (line-level) files.
   - Uses WhisperX (or similar OpenAI Whisper implementation with `word_timestamps=True`) to force-align the provided text to the `vocals.wav` stem.
   - Outputs an Enhanced LRC (word/syllable-level) mapping for the MIDI compiler.
4. **Instrument Transcription:** `basic-pitch` extracts raw MIDI from the stems. A down-charting algorithm quantizes these notes to 5-lane Rock Band frets (Green, Red, Yellow, Blue, Orange) across 4 difficulties (Expert -> Easy).
5. **MOGG Generation:** `ffmpeg` mixes the stems into a single 10-channel Ogg Vorbis stream mirroring the "311 - Down" DLC layout (ch0-1 silent kick/snare, ch2-3 stereo drum kit, ch4 mono bass, ch5-6 stereo guitar/backing, ch7-8 stereo vocals, ch9 silent fake/crowd), which `mogg_builder.py` wraps with the proprietary v10 (unencrypted) MOGG header + OggMap (see [mogg_audio_format.md](mogg_audio_format.md)).
6. **STFS/CON Packaging & Validation:** `con_packer.py` assembles the hierarchical `songs/{song_id}/` structure containing `.mid`, `.mogg`, `songs.dta` (with the 311-compatible 10-channel multitrack mapping `((drum (0 1 2 3)) (bass (4)) (guitar (5 6)) (vocals (7 8)))` plus 10-entry `pans`/`vols`/`cores`), plus `gen/` milo + PNG assets re-used from the signed `SmellsLikeNirvana_rb3con` template. The `.mid` chart (built by `midi_generator.py`) is a 7-track file mirroring "311 - Down": track 0 = tempo map (named `song_id`, 4/4 + 120 BPM), then `PART DRUMS` / `PART BASS` / `PART GUITAR` / `PART VOCALS`, `EVENTS`, `BEAT`. The `EVENTS` track carries the mandatory Rock Band text markers `[prc_intro]`, `[music_start]`, `[prc_verse_1]`, `[preview]`, `[prc_chorus_1]`, `[prc_outro]`, `[music_end]`, and `[end]` (final event); the `BEAT` track emits one quarter-note marker per beat (pitch 12 downbeat vel 101, pitch 13 other beats vel 100, 480-tick spacing). `PART DRUMS`/`PART GUITAR`/`PART BASS` are placeholders emitting one note per difficulty (60/72/84/96 = EasyStart/MediumStart/HardStart/ExpertStart) because LibForge's `RBMidConverter` builds per-difficulty gem arrays lazily — a single pitch-60 note left 3 of 4 difficulty slots null and NRE'd (see [forgetool_compat.md](forgetool_compat.md)). `songs.dta`'s `(rank ...)` values are no longer hardcoded 150 (which rendered every song as difficulty 1 of 6): `difficulty.py` parses the chart MIDI with a running-status-aware SMF parser (tolerant of the truncated final events RB3 charts contain) and maps per-instrument note density through level bands 1-6 (`_DENSITY_BANDS`, calibrated to "311 - Down": drum 30.2 nps -> level 5, guitar 18.9 -> 4, bass 9.9 -> 3, vocals 3.35 -> 2), emitting each level band's midpoint rank; `band` = hardest charted instrument (not mean). The CON's `_keep.png_xbox` is a Milo HMXBitmap texture (32-byte header + byte-swapped DXT1/DXT5), generated from the `--album-art` image or the default "Chris Prime Custom" art via `texture.py` (see [con_stfs_format.md](con_stfs_format.md)). Payloads are placed using the STFS logical->physical block mapping (see [con_stfs_format.md](con_stfs_format.md)); the staged milo is the true template milo and is verified parseable by a LibForge replication (see [forgetool_compat.md](forgetool_compat.md)). `stfs_validator.py`, `forge_simulator.py`, and `pytest` provide automated validation of STFS file tables, parent directory references, and payload placement.

## Known Crash & Fix Notes
- **No audio preview + instant 0% completion (v0.0058):** The CON converted and installed (RB4DX + ForgeTool) but the song had no audio preview in the song list and "completed instantly" at 0%. Root cause: the MOGG's embedded Ogg used ffmpeg's default ~1s / 56KB libvorbis pages (granule deltas ~31000-36000), which RB's Milkshake audio engine can't decode. Fix: `mogg_builder.py` forces small ~4KB pages (`-page_duration 40000`, `PAGE_DURATION_US`) matching stock "311 - Down" moggs (~2048-3072 sample granules/page), and `dta_writer.py` now derives `(song_length ...)` from the real MOGG via `read_mogg_duration_ms()` instead of a hardcoded value (see [mogg_audio_format.md](mogg_audio_format.md)).
- **RB4 vocal-fretboard crash (v0.0056):** After the MOGG fix, RB4 still crashed the moment the vocal fretboard loaded. Working hypothesis: `songs.dta` advertises `PART DRUMS` / `PART GUITAR` / `PART BASS` at rank 150 but the chart contained only `PART VOCALS`, so RB4 (via ForgeTool PKG conversion) had nothing to load for the advertised parts. Fix: `generate_vocal_midi()` now emits placeholder instrument tracks so every advertised part resolves to a real MIDI track.
- **ForgeTool CON→PKG NRE in `RBMidConverter` (v0.0057):** The v0.0056 placeholder (one note at pitch 60) fixed the missing-track crash but introduced a new ForgeTool crash: `System.NullReferenceException` in `HandleDrumTrk` / `HandleGuitarBass`. Root cause: `RBMidConverter` stores `gem_tracks` as a 4-element array (Easy/Medium/Hard/Expert) populated lazily per difficulty seen, so a single Easy note left Medium/Hard/Expert null and `gem_tracks.Select(g => g.ToArray()).ToArray()` threw. Fix: `build_placeholder_track()` emits one note per difficulty (60/72/84/96 = EasyStart/MediumStart/HardStart/ExpertStart from RBMidConverter.cs), guaranteeing all four difficulty slots are non-null.
- **"Fretboard flashes then instant 0%" chart-side root causes (v0.0061):** Two MIDI-side bugs were found behind the persistent in-game symptom. (1) `step4_sync.py` wrote synced word entries under `time`/`beat_time` but without `start`/`end`/`pitch`, so `generate_vocal_midi()` fell back to `start=0.0`, `pitch=60` for every word — the entire PART VOCALS chart was a blob at tick 0. It now emits real `start`/`end` (from `word_segments`) and `pitch` (from Basic-Pitch `note_events` in `vocals_cache.json`). (2) The chart lacked the mandatory EVENTS text markers and its BEAT track carried no notes. `midi_generator.py` now emits `[prc_intro]`, `[music_start]`, `[prc_verse_1]`, `[preview]`, `[prc_chorus_1]`, `[prc_outro]`, `[music_end]`, `[end]` (final event) in EVENTS and a real BEAT track (pitch 12/13, 480-tick spacing), mirroring "311 - Down". Missing `[preview]` kills the song-list preview; missing `[music_end]`/`[end]` makes the song finish instantly at 0%.

## Verification & Versioning
- Byte-level checks confirm all 5 payloads in the rebuilt CON match the staged files.
- ForgeTool GUI is the external truth: it must load the CON without exception, and "CON to PKG Conversion" must not throw in `MiloFile.ParseDirectory`.
- Every fix that touches packaging lands with a version bump (`autorb/version.py`) and a `CHANGELOG.md` entry documenting the exact offset/field fix.
