## 2026-08-15 — Rock Band difficulty-charting guidelines captured (v0.0.92)

**What:** Added `[[difficulty_charting]]` knowledge page documenting the authoritative Rock Band / RBN (C3) rules for deriving Hard/Medium/Easy from an Expert chart, sourced from the C3 "Guitar and Bass Authoring", "5-Lane Keyboard Authoring", "Guitar/Bass Review Process" docs, the Rock Band Customs Blog, the mariteaux "Authoring Lower Difficulties" tutorial, and the DowncharterPlus reference tool. Core rules captured: Expert-first cascade (Expert→Hard→Medium→Easy, copy-then-simplify), **lane consistency** (every Expert lane must appear ≥1 gem in every lower difficulty), per-difficulty gem-focus (Easy=top3 / Medium=top4 / no chords on Easy / no 3-note chords on Hard-Medium / HOPOs→strums on Medium-Easy), and **sustain pull-back** (quarter-gap on Medium, +1/16 on Easy, 1/16 on Hard). Also documented the **gap**: AutoRB's `DifficultyReducer` currently uses absolute density caps + lane drops and does NOT implement these rules, and the packed-MIDI encoding loses drum/keys difficulty differentiation. Updated `[[instrument_charting]]` to cross-link and to record the guitar-vs-keys count mismatch (separate pyin passes + tuning filtering) and the `crepe`-missing root cause of low counts.

**Why:** User confirmed the lower difficulties are not being created from Expert following Rock Band guidelines, and that guitar/keys/bass counts are far too low. The guidelines are the spec the reducer must eventually implement; capturing them now (with sources) prevents re-deriving and gives the next implementation pass a concrete checklist. `crepe` install was attempted but failed to build (missing `pkg_resources`/old setuptools) — installing `setuptools` + `crepe` is the lever for real guitar/bass density.

These are documented as known limitations rather than hidden.

## 2026-08-15 — Instrument charts wired into pipeline + batch multi-song PS4 packaging (v0.0.92)

**What:**
- **Instrument transcriptions are now integrated end-to-end.** Step 4b of `autorb/cli.py` produces guitar/bass/drums/keys charts (new `keys.py` derives a keys chart from the "other" stem since Demucs can't separate guitar from keys) and passes them into `generate_vocal_midi` → `build_all_instrument_tracks`, the validation MIDI, and `build_clone_hero_song`. `generate_vocal_midi` gained `keys_charts` + `freestyle_drums` params; empty charts fall back to the placeholder track so ForgeTool's CON→PKG conversion no longer `NullReferenceException`s. New `--freestyle-drums` CLI flag makes the drum track a single placeholder note (drum freestyle throughout). `PART KEYS` uses the true 2-octave C2–C4 piano roll (pitch 36–60); other instruments use the Expert 60 / Hard 72 / Medium 84 / Easy 96 pitch-base convention.
- **`--package-con-dir` batch packaging mode** (`build_ps4_pkg_from_con_dir` in `con_packer.py`): packages every `.con` in a folder into **one multi-song PS4 PKG** with no pipeline inputs required. It parses each CON's STFS payloads (`read_con_payloads`, matching our writer's layout: name ASCII at 0x00, flags at 0x28, size BE at 0x34, startBlock LE at 0x2F, **parentDir int16-BE at 0x32**), merges their `songs.dta` (`combine_songs_dta`), and rebuilds a correctly-linked multi-song CON (`package_con_multi`). The directory-entry format was reverse-engineered from GameArchives' `STFSPackage.cs`: ordinal = entry position, `parentDir` references the parent's ordinal (root = 0xFFFF = -1), and the reader breaks at the first zero-byte entry — so entries must be contiguous from index 0. Files are flagged `0x40` (sequential blocks) to **avoid depending on the STFS hash table** entirely, which makes multi-song CONs robust regardless of the template's hash-table coverage. Verified: a 2-song combined CON extracts both songs via `con2gp4` and builds a valid PKG.
- README "Batch packaging: many CONs → one PS4 PKG" section documents the exact run-pipeline-N-times → one `--package-con-dir` command workflow (flows into release notes via `gen_release_notes.py`).
- `build_ps4_pkg` now returns the real `UP8802-CUSA02084_00-<id>.pkg` path ForgeTool actually writes (the old 16-char name was a non-existent path).

**Why:** The user wants to sequence several pipeline runs to generate CONs, then one command to ship them as a single PS4 song pack (and demo to friends soon). Previously instrument charts were computed but discarded before the MIDI assembly, so tracks were empty placeholders. ForgeTool's `con2pkg` only accepts a single CON, so a multi-song PKG requires a multi-song CON first. The GameArchives layout was the missing key — without correct `parentDir` links every file references a "non-existent directory" and ForgeTool rejects the CON.

## 2026-08-14 — Instrument transcription infrastructure implemented (v0.0.92)

**What:** Added complete instrument transcription package `autorb/transcribe/instruments/` with all modules needed for Guitar, Bass, and Drum chart generation per Harmonix authoring standards:

- **guitar.py**: CREPE-based pitch detection at onsets, chord detection (simultaneous onsets ≤50ms), HOPO detection (adjacent lanes ≤120ms, same direction), hold detection (energy decay threshold), solo/BRE detection (density-based), automatic tuning/capo detection from pitch distribution, 5-lane mapping with difficulty pitch ranges.
- **bass.py**: Same pipeline optimized for bass (fmin=30Hz, fmax=300Hz), hold detection more sensitive (bass sustains are common), HOPOs, solo/BRE.
- **drums.py**: Multi-band onset detection (madmom primary, librosa fallback), frequency-band drum element classification (kick 40-100Hz, snare 150-250Hz+broadband, hi-hat 6-12kHz, ride 4-8kHz, crash 4-8kHz loud+long, toms 80-300Hz), fill detection (≥3 multi-lane hits/500ms → overdrive phrases), hi-hat open/closed state transitions, solo/BRE detection.
- **onset_detection.py**: Shared librosa (spectral flux) and madmom (CNN) onset detection with merging (min_interval) and strength filtering.
- **pitch_to_lane.py**: Automatic tuning detection (clusters pitches around expected open strings), capo detection (global semitone shift), pitch→fret/string mapping, 5-lane mapping per difficulty (Expert base 60, Hard 72, Medium 84, Easy 96; open=67).
- **drum_classifier.py**: Spectral feature extraction (centroid, rolloff, bandwidth, ZCR, band energies), rule-based element classification, fill detection, hi-hat state tracking.
- **difficulty.py**: Progressive reduction Expert→Hard→Medium→Easy with density caps (16/14/10/6 notes/sec), protected notes (HOPOs, chords, holds, solos, BRE, fills), grid quantization.
- **midi_generator.py additions**: `build_instrument_track(charts, instrument, count_in_ticks, time_to_tick)` builds a single MTrk containing all 4 difficulties distinguished by pitch range (Expert=base, Hard=base+12, Medium=base+24, Easy=base+36; drums fixed pitches). `build_all_instrument_tracks()` returns [drums, bass, guitar] tracks ready for MIDI assembly.

**Dependencies added to requirements.txt**: `crepe>=0.0.12`, `madmom>=0.16.1`, `scikit-learn>=1.3.0` — all with graceful fallbacks (crepe→pyin, madmom→librosa, sklearn→builtin logic).

**Why:** Implements Milestones 1-3 of the instrument charts roadmap (Guitar/Bass/Drums MVP). The infrastructure is complete and tested (imports, unit test structure); ready for integration into cli.py pipeline where it will replace placeholder instrument tracks with full transcriptions. This is the foundation for playable guitar/bass/drums in the generated CON/PKG.

(3) `_reanchor_late_words`: rule 1 = earliest **voiced-validated** onset in `(prev_end, start]` bounded by `start−2.0s`; rule 2 = `_last_pitch_unit_boundary`, a settled-future detector (pitch ≥3.5st from the median of the stable [ptp≤2st] window 0.10–0.35s ahead), then prefers a real onset within ±0.15s when guarded (never past next word / behind prev word). (4) `_clip_and_extend_word_ends` sets `end = next_start − 0.02` when no voiced end exists and a next word does, and runs THREE times (before gap moves, between gap and late moves, after late moves). (5) `test_every_word_start_snaps_to_real_onset` now also accepts pitch-boundary placements.

**Why:** The v0.0.86 chart still failed 9 user-reported ORS sync issues. ## 2026-08-11 — Robust vocal-pitch: harmonic-misread gates + outlier-rejected contour (v0.0.83)

**What:** Updated `[[vocal_alignment]]` with a v0.0.83 section and re-measured the rebuilt Open Road Song chart. The trust gate (`PYIN_PROB_THRESH` per segment + mode≈median) was necessary but NOT sufficient: a harmonic/bleed *split* reading passes it per-segment while the syllable as a whole is noise. Three-part fix in `autorb/transcribe/pitch_tracking.py`:
1. **Multi-segment spread rule** (`MAX_SYLLABLE_SPREAD_ST=6.0`) — a syllable whose segments span > 6 st is untrusted; a real vocal slide never jumps that far inside one syllable.
2. **Robust contour anchors** — `build_melodic_contour_from_syllables` rejects anchors that deviate > `CONTOUR_OUTLIER_ST` (7 st) from the local-median of their ±2 neighbors (`CONTOUR_ANCHOR_WINDOW`), *before* interpolating. A single contaminated anchor used to warp the whole contour (Open Road Song's "road"=72 = 3rd harmonic of A3=57 dragged the contour up and pulled untrusted neighbors like "pen"=64 with it).
3. **Trusted contour-check** in `resolve_syllable_pitches_with_fallback` — a trusted reading survives only if its first note is within 7 st of the robust contour, else it is reclassified as untrusted and resolved via BP/contour fallbacks.

Key measured results on the rebuilt chart (v0.0.83): consecutive vocal jumps ≥ 5 st **18 → 10**; vocal range **50..78 → 50..64** (72/76/78 were harmonics); first-phrase "hit eighty on the open road" `50→61→54→64→72` → `57→57→57→56`; ending "road/song" `66→78→76→52→61` → coherent `63→64→64` ascent. The low "As" dip (50 vs contour 56, dev 6.2 st) is a genuine melody element and is intentionally preserved by the 7-st threshold — do not lower the threshold expecting to catch it.

**Why:** User play-tested the PS4 chart and reported vocal pitches "jump" note-to-note. The previously-documented v0.0073 fix (per-word pyin trusted on confidence+mode-consensus) stopped most jumps (61→28) but the remaining 10-18 jumps were exactly the self-consistent harmonic misreads that no per-segment check can catch. Also documented a recurring debugging trap: `output/` frequently holds a different song's build (Brian Wilson), so `test_quality_validation.py` failures against `output/` are data-dependent, not code regressions — 4 such failures exist on the pre-fix baseline too.

## 2026-08-11 — Voiced-onset snapping + LRC-line sustain fix + quality-validation suite (v0.0.82)

**What:** Updated `[[vocal_alignment]]` with a new v0.0.82 section covering two `step4_sync.py` fixes and added `tests/test_quality_validation.py` (10 tests, currently 103 total passing):
1. **Voiced-onset snapping** — `_detect_vocal_onsets` now filters onsets to those with a pyin-confident (prob > 0.5) voiced frame within 0.25s (`VOICED_ONSET_PROB`/`VOICED_ONSET_WINDOW`). Root cause: `onset_detect(backtrack=True)` places an onset on the envelope floor before the peak; for the first word of a song that floor is pre-sound silence or an unvoiced consonant, so the note led its own pitch. Open Road Song's "Tonight" was snapping to 0.232s vs its true first voiced frame at 0.488s; it now charts at 0.534s (0.076s from the LRC).
2. **LRC-line sustain membership uses `raw_start`** — `_clip_and_extend_word_ends` extends each LRC line's last word toward the next line's timestamp, but onset snapping can pull the *next* phrase's first word before its LRC timestamp, mis-assigning it as the previous line's last word and silently disabling the sustain extension. Each refined word now records its pre-snap `raw_start` and line membership uses it.
Also documented the debugging trap: `output/` had been overwritten by a Brian Wilson run, so the Open Road Song chart was being driven by a 291s stem/cache — check stem/cache/tempo-map durations against the source audio before trusting quality-test failures against stale artifacts.

**Why:** The quality-validation suite exposed two real chart bugs (first word 0.38s early; line-final sustains chopped). The onset fix corrects what v0.0070's "charts at 0.232s ≈ the true attack" had wrongly enshrined; the raw_start fix makes the v0.0072+ sustain behavior actually engage.
