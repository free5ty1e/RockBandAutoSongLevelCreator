# Rock Band Customs Domain Knowledge

## Target Format: Xbox 360 CON (STFS)
We target the Xbox 360 CON format because it is the universally accepted standard for modern custom songs. Community tools like Onyx Music Toolkit can ingest Xbox 360 CONs and effortlessly convert them to PS3, PS4 (Rock Band 4 Deluxe), Wii, or Clone Hero formats. 

## Known Tooling Quirks & Technical History
- **The ForgeTool Zlib Crash:** Older custom songs or tools often packed files using "Stored" (uncompressed) Zlib blocks. When converting these to PS4 using ForgeTool GUI, it crashes with a "Zlib block inflation not implemented yet" error because ForgeTool lacks the logic to read Type 0 blocks.
- **The Onyx Fix:** Onyx acts as a "cleaner." Processing files through Onyx rewrites the internal Zlib blocks into standard Deflated formats that tools like ForgeTool can decompress without crashing. Note: Onyx does not have a dedicated "PS4" button; users target Xbox 360 in Onyx to standardize the CON, which is then passed to PS4 packaging tools. Our AutoRB tool must ensure its output mimics this clean, deflated Zlib standard to prevent downstream crashes for users.

## MIDI Requirements
- **PART VOCALS:** Requires syllable-by-syllable note placement. Pitch matters for harmonies, but for basic vocals, timing and text injection (via MIDI lyric events) are the primary requirements. AutoRB now writes real `start`/`end`/`pitch` per word into `synced_lyrics` (from word segments + Basic-Pitch note events); a chart with every note at tick 0 / pitch 60 renders as a flash of the fretboard then an instant 0% finish.
- **Phrase markers are pitch 105 on PART VOCALS.** A vocal phrase is opened with `note_on 105` (vel > 0) and closed with a proper **`note_off 105`**. Closing with `note_on 105 vel 0` (0x90/00, running-status) instead of a real `note_off` (0x80/00) leaves every note outside any phrase and kills vocal scoring entirely — the v0.0061 stale output had 18 opens and 0 real closes. C3 authoring docs also warn a phrase marker shorter than a quarter-note triggers a "Vocal Phrase Overlap" error. Phrase boundaries should be the source of truth for phrasing (each `.lrc` line = one phrase, with 2-bar measure windows as the fallback).
- **RB4's freestyle-vocals guide lines are gated by `HasFreestyleVocals` in the PS4 `songdta_ps4` binary — NOT by dta key metadata.** The RB4 manual describes the guide lines ("sing any of the pitches indicated by the guide lines... harmonious with the structure of the song") as part of the **Freestyle Vocals** feature, which is per-song gated ("Freestyle Vocals are available for songs that support it, as indicated in the Music Library"). The `songdta_ps4` binary carries a `HasFreestyleVocals` bool (`SongDataWriter.cs:42`); the game-side key analysis that draws the guide lanes (root/3rd/5th intervals, per Harmonix patent US 2010/0304810) runs on charted vocal notes once the feature is enabled. **Important:** the earlier theory that `(vocal_tonic_note N)` + `(song_tonality 0|1)` in `songs.dta` enable the guide lines is **wrong for PS4** — those fields have no slot in the `songdta_ps4` binary and `SongDataConverter` silently drops them (they're RB3-only metadata). ForgeTool historically hardcoded `HasFreestyleVocals = false`, so no ForgeTool-converted custom ever advertised freestyle support; the vendored tool now reads `(freestyle_vocals 1)` from `songs.dta` (written by AutoRB only under the `--generate-freestyle-vocals` flag). `vocal_tonic_note`/`song_tonality` remain useful as RB3-side key metadata (key detection via `autorb/export/key_detect.py`, chromatic 0-11 / 0=major, 1=minor) but do not drive RB4's guide.
- **EVENTS markers (mandatory):** Every chart must carry the text markers `[prc_intro]`, `[music_start]`, `[prc_verse_1]`, `[preview]`, `[prc_chorus_1]`, `[prc_outro]`, `[music_end]`, and `[end]` (as the final event). A missing `[preview]` kills the song-list preview; a missing `[music_end]`/`[end]` makes the game finish the song instantly at 0% (with the full-combo jingle).
- **BEAT track (real markers):** Stock RB3 charts carry one quarter-note marker per beat in `BEAT` — pitch 12 on the downbeat (vel 101) and pitch 13 on other beats (vel 100), spaced 480 ticks apart at 120 BPM. A named BEAT track with no notes does not satisfy the engine. Each note is `note_on` at the beat tick and `note_off` 320 ticks later.
- **Difficulty ranks:** `songs.dta` `(rank ...)` values drive the in-game difficulty dots. AutoRB computes per-instrument ranks from chart note density via level bands 1-6 (`difficulty.py`) and sets `band` to the hardest charted instrument — never a hardcoded value that renders every song as "1 of 6".
- **Instrument Lanes:** 5 lanes (0=Green, 1=Red, 2=Yellow, 3=Blue, 4=Orange).

## Count-In / Lead-In is Audio, Not a MIDI Marker
Per C3/RBN "Mix and MIDI Setup" docs, the count-in is **prepended to the audio** (the TRKS/MOGG), not authored in the chart: a 2-measure "one-two, one-two-three-four" click track recorded at the tempo of the song's first bars, then 2 measures of lead-in silence for the menu countdown. `[music_start]` fires the crowd cheer — currently at tick 0, so the cheer happens instantly and there is no count-in. The 311 reference chart offsets its markers (e.g. `[prc_intro]` @3840, `[music_start]` @5280) because the audio carries the count-in.

## Tempo Maps & Sync Accuracy
A single averaged BPM in the MIDI tempo track causes **progressive lyric/vocal drift** on the real console: AutoRB's beat-tracked `tempo_map.json` has 534 jittery values (min 152, max 184.6, avg 169, dominant ~172.3 BPM). Stock charts like "311 - Down" carry a **dynamic tempo map** — recurring `set_tempo` events (often changing every ~2 bars) that keep the BEAT grid and chart synced to the audio. Since v0.0063 `midi_generator.py` writes the real per-interval tempos as `set_tempo` events (one per beat, deduped), derives every note/beat tick from the beat grid (tick 480*i == `beat_times[i]`), and prepends a virtual beat at t=0 so tick 0 == audio sample 0 (the librosa tracker starts at ~0.9 s, which otherwise shifts the whole chart early by that constant lead-in). Verified: word ticks round-trip to their audio timestamps within 1.3 ms across the full song. The BEAT track length is also derived from the tempo map, not a hardcoded 120 BPM (that left the grid short at faster tempos).
