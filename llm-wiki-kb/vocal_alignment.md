# Vocal Alignment & LRC Processing

## Standard vs. Enhanced LRC
- **Standard LRC:** Provides line-level timestamps. Example: `[00:12.00] This is an open road song`
- **Enhanced LRC:** Provides word/syllable-level timestamps. Example: `[00:12.00] <00:12.00> This <00:12.20> is <00:12.40> an <00:12.60> o<00:12.70>pen <00:13.00> road <00:13.50> song`

## AutoRB's AI Alignment Strategy
Rock Band requires MIDI events for every spoken syllable so the in-game lyric tubes scroll correctly. Standard LRCs are insufficient. 

To solve this:
1. AutoRB ingests the user's Standard LRC (which provides the 100% accurate lyrics, avoiding AI hallucination on the text itself).
2. The pipeline extracts the `vocals.wav` stem.
3. A forced-alignment model (like WhisperX) listens to the vocal stem and maps precise start/end timings to the words provided in the Standard LRC.
4. This data is mapped to MIDI pitch notes on the `PART VOCALS` track. Each `synced_lyrics` entry now carries real `start`/`end` (from the word segments) and `pitch` (from the Basic-Pitch `note_events` in `vocals_cache.json`, **max-overlap** note lookup, v0.0068) — `step4_sync.py` emits these fields explicitly (v0.0061). Before that fix the entries only had `time`/`beat_time`, so `generate_vocal_midi()` fell back to `start=0.0`, `pitch=60` for every word and the entire 284-note chart was a blob at tick 0 (the "fretboard flashes then instant 0%" symptom).

## Onset-Snapped Timing & Pyin Guard (v0.0068 → v0.0070)
> **Updated in v0.0.85** — the voiced-onset filter, the snap window (0.45s → 0.90s), the snap rule (earliest → latest onset at-or-before), and the previous-word floor (end → true onset + `MIN_WORD_SEP`) all changed; see "Audio Is the Source of Truth for Word Timing (v0.0.85)" below. This section is the historical v0.0070 record.
WhisperX word boundaries are systematically LATE relative to the true sung onset (median ~80ms, tail up to ~400ms), which reads as lyrics/notes drifting behind the audio in-game. `step4_sync.py` snaps each word's start to a real vocal onset within a 0.45s-before / 0.05s-after window (`_refine_word_timing`), with two hard constraints:
- **Never back into the previous word's sung region** (`prev_sung_end - MIN_WORD_GAP`) — Basic-Pitch often merges a fast following word (e.g. "Tonight I") into a single sustained note, and snapping into that note would steal the neighbour's sung window.
- **Only when WhisperX is measurably late** (`ONSET_SNAP_EARLY_MIN` = 0.03s) — an on-time alignment is left alone.

**v0.0070 root cause: Basic-Pitch onsets are themselves late.** The v0.0068 snap chose the *nearest* Basic-Pitch note onset, but Basic-Pitch misses the earliest part of the sung attack (consonant + first energy). On Eve 6 "Open Road Song" the singer attacks "Tonight" at **0.23s** (librosa onset on the vocal stem; confirmed by RMS ramp), WhisperX aligned the word at **0.61s**, and Basic-Pitch's first onset was **0.58s** — so the nearest-onset snap moved the note only 30ms, leaving it **~350ms late** (charted 5.037s vs real sung onset ≈ 4.68s) on top of the ~80ms median lag across all 284 words. The v0.0069 "file is internally consistent" conclusion was right but incomplete: word↔note↔MOGG agree *because all three share the late sources*. The ground truth is the stem's attack.

**Fix:** `step4_sync.py` now runs librosa onset detection on the vocal stem (`_detect_vocal_onsets`, sr=22050, `onset_strength` + `onset_detect(backtrack=True, delta=0.05)`) and snaps each word's start to the **earliest** onset in the search window (the true attack), still bounded by the previous word's sung end. The nearest-Basic-Pitch snap is retained only as a fallback when no stem is available. `cli.py` passes `stems["vocals"]` into `run_step_4(...)` so the snap always uses the real stem (works with `--skip-vocals` cached runs). Result: first word charts at 0.232s; median word-vs-onset lag dropped **80 → 20ms**; charted first note now lands ≈ the actual sung onset.

Word ends extend across all notes that *begin inside* the word's own span, so multi-syllable words keep their full pitch window without widening into the next word. Words are processed in chronological order and `prev_sung_end` tracks the charted end so the constraint is strict.

**Pitch = max-overlap note.** Demucs vocal stems carry reverb/bleed, so Basic-Pitch emits several simultaneous notes (one true vocal, the rest harmonics/echo). The v0.0061 weighted-median lookup let a spurious neighbour near the window *centre* drag the reading off; the v0.0068 `pitch_at` picks the note with the largest overlap over the word window — the sustained sung note wins.

**v0.0073 root cause: Basic-Pitch (via `pitch_at`) is a poor *primary* pitch source.** After the v0.0072 sync fix landed, the PS4 user still saw the vocal fretboard *pitch* changing arbitrarily — many lyrics charted notes that don't match what the singer actually sang. Auditing the 284-word "Open Road Song" chart showed pitches were taken straight from Basic-Pitch, whose stem output is contaminated by harmonics, reverb, and guitar bleed; a `+0.1s` window extension routinely grabbed the *next* word's note ("as" charted the following word's 80). The chart had 61/283 consecutive jumps ≥ 4 st (up to ±24) and a 33-st range. The old pyin guard (below) required `pyin_confidence >= 0.8` and so **never fired (0/61 eligible words)**.

**v0.0073 fix: per-word pyin is primary, BP is an octave-snapped fallback, contour is last.** `step4_sync.py` now computes the full pitch in `_resolve_pitches` over each word:
1. **librosa pyin is primary** — runs once per word over a window *clipped to the next word's charted start* (mirroring the charted note duration, so a word's window never leaks into a neighbour's). A reading is **trusted** only when ≥ 2 voiced, confident (`prob > 0.5`) frames exist AND the rounded mode is within 1 semitone of the median (`PYIN_MODE_AGREE_ST`). This keeps real vibrato/slides/sustained vowels while rejecting split readings (fundamental + strong harmonic).
2. **Basic-Pitch fallback, octave-snapped to the melodic contour** — for words without a trusted reading, the max-overlap BP note (full `[start,end]` span, as in the validated prototype) is snapped to the in-range octave copy nearest the **melodic contour** (a linear `interp1d` through trusted words, constant extrapolation at the ends) and accepted only within `CONTOUR_SNAP_ST` (3 st). This turns octave-flipped/contaminated BP notes into sane, in-key pitches.
3. **Contour last** — if no BP candidate is near the contour, the word follows the contour, clamped to C3..C6 (`VOCAL_MIDI_MIN/MAX` = 48/84).

Measured on "Open Road Song": consecutive jumps ≥ 4 st **61 → 28/283**, range **50..83 → 50..78**, max jump +24 → +14, **0/284 off the A-major scale**, and repeated phrases now sing the same notes while pyin-confirmed melody is preserved (low A2 on "As", held F3 on "song", F#5 "roaaaad"). The old `_annotate_pyin_pitches` guard in `vocals.py` was removed (step4 computes pyin itself over the onset-snapped windows); the "This [67.5] / is [56.2]" example below is a *genuine* melodic accent, not an artifact to suppress.

Measured on Eve 6 "Open Road Song" (v0.0070): first word "Tonight" charts at 0.232s ≈ the true 0.23s sung attack (was 0.58s pre-v0.0070); median word-vs-onset lag 20ms (was 80ms). Remaining PS4-side symptoms (song-list preview silence, freestyle guide lines not rendering) are tracked separately in `rock_band_customs_domain.md` and `ps4-environment.md`.

## Overlap-Free Note Ends (v0.0072 root cause of the remaining in-game drift)
The onset snap (v0.0070) and the sparse tempo map (v0.0071) shipped, but the PS4 symptom stayed: first word right-on, every subsequent word *progressively later*. The tempo track was exonerated (the rebuilt chart round-tripped grid↔tempo-map↔ForgeTool `StartMillis`↔MOGG to <1ms), so the drift had to be in the note *positions* themselves. Tracing the charted note ticks back through the tempo map exposed it: `step4_sync.py` deliberately stretches word `end` times across the word's whole phrase (line 25 above), so a word's end routinely runs **past the next word's start** — "Tonight" ends at 0.940s while "I" starts at 0.853s and "feel" at 0.975s. `generate_vocal_midi()` computed each note's duration from that end, kept a running `last_tick = start + duration`, and emitted each note at `max(target_start, last_tick)`. Every overlapping pair therefore pushed the following note later, and the pushes **accumulated** across the whole song: index-aligned charted-vs-whisper error grew 0 → +84 → +11,143 ticks (0s → 5.2s → 8.4s) from first word to last — exactly the PS4 rate problem, and why the v0.0071 tempo change "didn't get any worse" (the drift was never in the tempo track).

**Fix:** `generate_vocal_midi()` precomputes every word's charted start/end ticks, then **clips each note's end to the next note's charted start** before emitting, so a note whose end overlaps the following word simply ends at the next word's onset instead of pushing it. Every `note_on` now lands exactly at `shifted_time_to_tick(start)` — its true sung onset. Rebuilt charted-vs-whisper error: med **+5.088s → 0.000s** (first/mid/last thirds all ≤ 68ms, onset-snap offsets only), and the charted "open road song" words land on the audio's real sung positions (48.1/50.8/80.0/85.6/91.3s) instead of 5-8s late. Regression test: `tests/test_vocal_midi.py::test_overlapping_word_ends_do_not_push_notes_late`.

## Voiced-Onset Snapping & LRC-Line Sustain Fix (v0.0.82)
Two step-4 fixes, both found by a new 10-test quality-validation suite (`tests/test_quality_validation.py`) run against a freshly-restored correct output dir (the `output/` dir had been overwritten by a *Brian Wilson* run whose 291s stems/cache were silently driving the Open Road Song chart — first word snapped to 0.232s against the LRC's 0.61s).

**1. Onset snapping must target VOICED onsets, not the envelope floor.** `_detect_vocal_onsets` uses `onset_detect(backtrack=True)`, which assigns an onset to the local envelope *minimum* before the peak. For the first word of a song that minimum is digital silence (pre-sound), and for many words it is the unvoiced consonant ("Tonight"'s "T"). The v0.0070 claim "first word charts at 0.232s ≈ the true 0.23s sung attack" was wrong: the stem's first *voiced* (pyin-confident, prob>0.5) frame is at **0.488s** (Basic-Pitch first note 0.43s), so a note at 0.232s led its own pitch by ~0.25s and its lyric line by 0.38s. Fix: `_detect_vocal_onsets` now keeps only onsets with a voiced frame within **0.25s** after them (`VOICED_ONSET_PROB=0.5`, `VOICED_ONSET_WINDOW=0.25`; pyin adds ~8.5s per step-4 run). "Tonight" now snaps to **0.534s** (0.076s from the LRC). Onset count for Open Road Song: 596 → 313.

**2. LRC-line sustain membership must use the RAW (pre-snap) start.** `_clip_and_extend_word_ends` extends the last word of each LRC line toward the next line's timestamp (minus a 0.10s breath gap) so held final syllables ("forgottennnn") aren't chopped at WhisperX's boundary. It silently stopped working because onset snapping legitimately pulls the *next* phrase's first word before its LRC timestamp ("I" in line "I press it to the floor" snapped to 6.50s, before the 6.65s line marker), so that word was counted as the previous line's last word and got the sustain instead of "pedal". Each refined word now carries `raw_start` (the pre-snap WhisperX start), and line membership uses it: "pedal" sustains to 6.50s (clipped to "I"'s snapped onset), "floor" to 11.33s. Both fixes keep the overlap-free clipping from v0.0072 intact (extended ends are re-clipped to the next charted start).

## Harmonic-Misread Gates & Robust Melodic Contour (v0.0.83)
The v0.0073 trust gate (per-segment confidence > 0.5 + mode≈median) was necessary but NOT sufficient: a harmonic/bleed **split** reading passes it per-segment while the syllable as a whole is noise. User play-testing of the PS4 chart still showed notes "jumping" — Open Road Song's first "eighty" read `[50, 61]`, the ending "road" read `[66, 78, 76]`, "song" `[52, 61, 60]`, and because trusted syllables were never re-checked, these contaminated anchors also **warped the melodic contour** (untrusted neighbors like "pen" got dragged to 64 by "road"=72 = the 3rd harmonic of A3=57). Three-part fix in `autorb/transcribe/pitch_tracking.py`:

1. **Multi-segment spread rule** (`MAX_SYLLABLE_SPREAD_ST=6.0`) — a syllable whose segments span > 6 st is untrusted. A real vocal slide never jumps that far inside one syllable (the C4→E4 test slide, spread 4, stays trusted).
2. **Robust contour anchors** — `build_melodic_contour_from_syllables` rejects anchors that deviate > `CONTOUR_OUTLIER_ST` (7 st) from the local-median of their ±2 neighbors (`CONTOUR_ANCHOR_WINDOW`), *before* interpolating. Local-median (not leave-one-out) is important: leave-one-out interp dropped a GOOD anchor ("o"=57) as collateral next to the two bad ones.
3. **Trusted contour-check** in `resolve_syllable_pitches_with_fallback` — a trusted reading survives only if its first note is within 7 st of the robust contour; otherwise it is reclassified as untrusted and resolved via the BP/contour fallbacks.

**Measured on the rebuilt Open Road Song chart:** consecutive vocal jumps ≥ 5 st **18 → 10**; vocal range **50..78 → 50..64** (72/76/78 were harmonics); the first-phrase mess `50→61→54→64→72` ("hit/eighty/open/road") is now `57→57→57→56`; the ending `66→78→76→52→61` ("road/song") is now a coherent `63→64→64` ascent; repeated phrases still sing the same notes. The remaining 10 jumps ≥ 5 st are all real line-break/gap boundaries or the intentional low-As dip.

**Tuning warning:** the "As" dip (50 vs contour 56, dev 6.2 st) is a *genuine* melody element preserved by the 7-st threshold — do NOT lower `CONTOUR_OUTLIER_ST` below ~7 expecting to catch harmonics; it would start flattening real melody dips like "As" and the opening descent.

## Charted Note Anchored to the Onset-Snapped Word Start (v0.0.84)
The v0.0070/v0.0.82 onset snapping fixed `word.start`, but `generate_vocal_midi()` **ignored it whenever the word had syllables**: each note was charted at its syllable `note_segment.start`, i.e. the **Basic-Pitch pitch onset**. BP onsets lag the true sung attack (measured on Open Road Song: median 0.000s, p90 +0.108s, worst **+0.598s** — "salt" 152.276 vs snapped word start 151.678), and on held words where pitch is only detected late the note landed near the word's *end* ("night" 56.912 vs 56.671, "song" 52.640 vs 52.359, "floor" 8.940 vs 8.754). The emitted MIDI was internally consistent (each `note_on` is immediately followed by its `FF 05` lyric meta at the same tick; earlier "+4s outlier" readings were an artifact of naive last-lyric tracking in analysis scripts, not the chart) — the words were simply charted at the wrong *onset*.

**Fix:** the **first** segment of a word's **first** syllable now starts at `word.start` (the true voiced sung onset); all later segments keep their own pitch-change times so syllable-internal slides/vibrato survive. After the fix every word's first note lands within 3ms (tick quantization) of its snapped start. Debugging aid: to read note↔lyric pairs from the chart correctly, capture the lyric meta that immediately follows each `note_on` at the *same tick* — a "last seen lyric" accumulator is shifted by one because `note_on` precedes its lyric meta.

## Audio Is the Source of Truth for Word Timing (v0.0.85)
The v0.0070/v0.0.82 onset snap and v0.0.84 word-start anchoring fixed the *machinery*, but user play-testing still showed words/phrases up to ~1s late and sustains both chopped and over-held. Audit of `step4_sync.py` against the actual vocal stem found the root causes were (a) a too-strict voiced-onset filter that dropped most real attacks, (b) a snap rule and a too-narrow window that left words at their late WhisperX times, and (c) sustains still driven by LRC line timestamps.

**Word starts — why 236/284 words were never snapped:** `_detect_vocal_onsets` kept only onsets with a `prob > 0.5` voiced frame within 0.25s; plosive attacks ("hit", "My", "pile") whose voiced vowel follows the onset late failed the gate, so only 51% of real onsets survived and ~29 words were charted 0.3-0.73s late. Now an onset is kept if a voiced frame (`prob > 0.3`) appears within **0.40s** OR the RMS energy rises **1.6×** above the song's relative noise floor within **0.30s** — unvoiced attacks are kept, silence-floor backtracking and bleed are still rejected. Onset count rose from 313 to 560 on Open Road Song.

**Word starts — snap rule & window:** the v0.0070 rule snapped to the **earliest** onset in the window, so widening the window (to absorb LRC/WhisperX offsets) made words snap to unrelated earlier attacks. The window was widened 0.45s → **0.90s** and the rule changed to snap to the **latest onset at-or-before the WhisperX boundary** (the nearest true attack on the early side) — correcting lateness without over-reaching. The floor is now the **previous word's true onset + `MIN_WORD_SEP` (0.08s)** instead of the previous word's possibly over-extended *end*, so an over-sustained previous word (e.g. "salt" end 155.77) can no longer block this word from snapping ("I search" now snaps to ~155.91) — and "I hit", which share one sung attack, still yield two non-zero notes.

**Word ends — audio-derived sustains:** `_clip_and_extend_word_ends` previously extended the last word of each LRC line toward the *next line's timestamp* (the old "LRC-line sustain"). Those timestamps over/under-shoot the real sustain, so "forgottennnn" was chopped short while "bored"/"mirror"/"alone" were held ~1.8s too long. Ends are now set by `_audio_word_end`: the **last voiced/RMS-energetic frame of the word's own region** `[start, next_start)`, then clipped to the next word's start. Sustains now follow the audio.

**Measured on Open Road Song (v0.0.85):** word starts moved a median 0.000s / mean −0.069s earlier (correcting lateness): "eighty" 46.43→45.98, "hit" 77.63→77.10, "hang?" 75.17→74.88, "air" 124.41→123.94, "out" 129.80→129.29. Over-sustains clipped to audio: "bored" 22.80→21.01, "mirror" 34.56→32.88, "floor" 11.52→9.87. Under-sustain fixed: "forgotten" 168.67→169.15 (its true voiced tail). No zero-length or overlapping notes. Note: long sustains on a phrase's *final* word (e.g. "song" held to ~121s) are genuine voiced content reaching the next word's boundary — the same behavior the old LRC-line extension produced — not a regression.

**New tests (4)** in `tests/test_sync.py`: large-LRC-offset snap, audio-tail sustain extension/clipping, snap-not-blocked-by-over-extended-previous-word.

**Missing-lyrics feature scoped to roadmap:** detect & fill un-represented vocal segments (e.g. the "YEAHHHHH!" after "forgotten") via WhisperX-transcribe + a pitched note — full plan in `.ai_memory/plans/missing_lyrics_detection_and_filling.md`, implementation deferred.

## Voiced-Primary Ends, Gap-Word & Late-Word Re-Anchors (v0.0.87)

The v0.0.86 chart still failed the 9-item "Open Road Song" playtest list. All fixes are in `step4_sync.py`; none hardcode times. **7/9 items fixed**; "song" (cut short) and "but home" (squashed) now **match the vocal-stem audio exactly** and await user judgment (the chart already holds beyond the sung audio, so no algorithm change can lengthen them without contradicting the audio).

**Word ends are voiced-primary (`_audio_word_end`).** A word's end is the **last confident-voiced frame** (`probs>0.25`) of its own region, breaking on **voiced gaps > `AUDIO_END_MAX_GAP=0.20s`**; RMS energy is only a fallback when the region has no confident voiced frames. This replaces the envelope-floor logic that let tails ring into the next phrase. **Lead-in fix:** frames before the first active frame do not start the gap timer — a word start is its *attack* and voicing can legitimately lag ~0.2s ("it"@140.16 voiced @140.38); counting the silence there false-triggered a break. Clips over-sustains: "listen" 138.67→138.28, "road" 186.67→186.34, "out" 143.6→142.62, "alone" tail 65.6→65.30.

**Gap words need a real phrase break (`_reanchor_gap_words`).** A word moves to its phrase's true attack only when the **next word starts ≥ `GAP_WORD_MIN_NEXT=1.0s` away** AND the grace window `[start+0.20, start+0.80]` is **vocally silent** (no voiced AND no RMS>floor) — the 0.20s grace skips the previous word's own voiced tail that would otherwise block the move. Then snaps to the first onset after the grace window (fallback `next−0.28`, capped `next−0.12`, floored `start+0.02`). "And" 20.94→23.80, "'Cause" 32.72→35.11. **Lesson:** earlier evidence-based variants (a voiced tail or ≥5 onsets in the gap) *over-fired* on legitimate words — "rain" 21.58→20.45, "settle" 22.09→21.01, "sun" 22.10→21.16 — and were reverted; only the current next-far + silent-grace rule survives.

**Late words re-anchor to a voiced-validated onset or a settled pitch boundary (`_reanchor_late_words`).** Rule 1: a start sitting `LATE_START_THRESH=0.30s`+ after the previous word's true end moves to the **earliest real onset** in `(prev_end, start]` bounded by `start − LATE_START_SEARCH=2.0s`, **but only if a confident voiced frame follows the onset within `ONSET_VOICED_AFTER=0.15s`** — the 40.91/41.03/41.29 onsets before "I"@41.54 are instrumental bleed in true silence (no voiced follow) and are rejected, while "out"'s 142.15 attack passes. Rule 2 (`_last_pitch_unit_boundary`): a **settled-future detector** — a frame's pitch must be ≥ `PITCH_UNIT_JUMP_ST=3.5st` from the median of the pitch it settles into over the next `PITCH_UNIT_PERSIST=0.25s`, windowed from `PITCH_UNIT_WINDOW_GAP=0.10s` ahead (so an in-progress gradual descent — the be/alone drop spans ~0.19s — is skipped, not averaged into the settled median), with the settled window **stable** (ptp ≤ 2st, rejecting vibrato/fast slides). The boundary is the LAST such frame, accepted when `0.25 ≤ (start−b) ≤ 0.80`. It then **prefers a real onset within ±0.15s** of the boundary when one exists (guarded: never past the next word or behind the previous word) — "on"@46.63 snaps to its 46.72 attack; "I"@58.17 keeps its boundary because its only nearby onset belongs to the next word. Rule 2's search runs `[prev.start, start]` (not `[prev.start, prev.raw_end]`) so the settled-future window can see the next word's hold.

**End ingestion + pass order.** `_clip_and_extend_word_ends` sets `end = next_start − 0.02` when `_audio_word_end` returns None but a next word exists (kills stale pre-move ends that blocked neighbors), clips `end > next_start`, and clamps `end < start` to `start + 0.2`. It runs **three times**: before gap-word moves, between gap and late moves (so a moved word's neighbor sees the corrected end — otherwise `_reanchor_late_words` re-snags And/'Cause onto the previous word's tail onset), and after late moves.

**Measured ORS chart (v0.0.87):** And 23.800–23.901, 'Cause 35.109–35.225, here 40.031–40.565 (I 41.285–41.587), be 63.043–63.344 / alone 63.367–65.295, listen 137.346–138.275, it 140.156–141.827 / out 142.153–142.617, road 185.689–186.340. Regression scan of every word moved >0.7s from WhisperX raw: And/'Cause/out intended; That®26.146, on®46.626, and®135.094 correct late-WhisperX phrases (true attacks ~26.26/46.74/135.35). 284 words, no zero-length/overlap/out-of-order notes.

**Ground-truth onset test accepts pitch boundaries.** `test_every_word_start_snaps_to_real_onset` additionally validates a word via `_last_pitch_unit_boundary` (evaluated against the word's *raw* start), because rule-2 re-anchors are real sung boundaries even when the vocal stem has no onset — "Drove" 209.93→209.26 is a 65→77 semitone drop with no detected onset. All 13 sync tests pass on fresh runs of both songs (`AUTORB_OUTPUT_DIR=output_fresh` / `output_fresh_bw`).

## WhisperX Chunked Alignment & No Doubled Lyrics (v0.0.86)

**LRC lines are phrase hints, not alignment segments.** v0.0.85 fed WhisperX **one segment per LRC line**, and `whisperx.align()` slices the audio at each segment's `start` — a hard boundary. A late LRC line dragged its entire phrase late, past the onset-snap recovery window (Brian Wilson's worst word charted **+1.8s late**). `vocals.py::_build_alignment_transcript` now groups LRC lines into **coarse ~60s chunks** (`ALIGN_CHUNK_SECONDS=60.0`) spanning the whole track; WhisperX aligns freely within each chunk, so LRC timestamps survive only as *chunk membership*, never as note positions. A single whole-track segment would be ideal but pushes the entire song through the wav2vec2 align model in one forward pass and **OOMs on CPU** (291s audio died mid-forward at ~1.3GB RSS on a ~7GB box; 198s survives) — hence chunking. Chunked alignment: 342 words in 12.5s, peak RSS 2.18GB. Measured on a fresh Open Road Song: word starts median 0.000s, p90 +0.027s, **0 words > 1s late** (previous tested build: 9).

**No doubled lyrics (the "I crack crack a window" fix).** `split_syllable_for_display` split a word into `#pitch_segments` notes; a single-syllable word with two pitch segments ("crack", "eighty" as 1 syllable) got a second note with an **empty lyric**, and Rock Band re-renders the *previous* lyric on empty text — doubling the word. It now never emits empty mid-word lyrics: words are split at **vowel boundaries** instead ("crack"→`cr`/`ack`, "eighty"→`ei`/`ghty`, pyphen-splittable words unchanged). Both fresh charts have **0 empty lyric events** (were 1-2 per doubled word).

**Syllable timing from WhisperX char alignments.** `segment_word_to_syllables` previously used vowel-weighted *proportional* timing inside each word. It now matches each dictionary syllable's text into the word's `whisperx_chars` alignments and derives **audio-true syllable boundaries**, rescaled onto the onset-snapped charted word bounds; pyphen remains the fallback. Syllable-internal notes therefore follow the sung rhythm, not an even split.

**Word-duplication guards (step4_sync.py).** WhisperX occasionally emits the same word twice for one sung occurrence and can split a melisma ("Well I'm-I'm lyin'") into two "I'm"s. Two dedup passes: `_dedup_consecutive_words` drops raw consecutive duplicates < **0.35s** apart before refinement; `_dedup_final_synced` drops post-snap identical words charted < **0.15s** apart (a melisma split snapping to one shared attack). Genuine re-articulated repeats ("fun fun fun", ≥ ~0.25s) are preserved — do not raise the thresholds; Brian Wilson's "fun fun fun" (0.27s gaps) and "Well I'm / I'm lyin'" (0.25s) are real lyrics.

**Onset-snap window widened** `ONSET_SEARCH_BEFORE` 0.90s → **1.50s** (safe: the rule only picks the *latest* onset at-or-before the boundary, and the previous-word floor blocks backtracking), recovering phrases > 0.9s off.

**Ground-truth validation tests (`tests/test_vocal_sync_fixes.py`, 13).** The two integration tests point at `AUTORB_OUTPUT_DIR` (default `output/`) and assert every charted word start lands on a real vocal-stem onset (`[-0.08, +0.12]`s window, ≤3 outliers) and no near-simultaneous (<0.15s) doubled words exist. They **fail on stale/pre-fix artifacts and pass on a fresh run** — Brian Wilson's previously-worst "a" (+1.798s) now passes. Known accepted edges: a whisperx-**early** word ("hit", ~0.2s) cannot be caught by the at-or-before snap; genuine repeated lyrics survive the dedup by design.

## Placeholder Instrument Tracks (required for RB4)
The `.mid` chart emitted by `generate_vocal_midi()` also includes placeholder `PART DRUMS`, `PART GUITAR`, and `PART BASS` tracks even though the vocals pipeline does not chart real instruments. Rationale: `songs.dta` advertises drums/guitar/bass at rank 150, and RB4 (via ForgeTool PKG conversion) crashed when the vocal fretboard loaded if an advertised part had no corresponding MIDI track. Every instrument advertised in `songs.dta` must have a loadable chart track, even if it is just a placeholder. The MIDI header track count is now 7 (v0.0061), mirroring "311 - Down": track 0 = tempo map (named `song_id`, 4/4 + 120 BPM), then `PART DRUMS`, `PART GUITAR`, `PART BASS`, `PART VOCALS`, `EVENTS`, `BEAT`. The `EVENTS` track carries the mandatory text markers `[prc_intro]`, `[music_start]`, `[prc_verse_1]`, `[preview]`, `[prc_chorus_1]`, `[prc_outro]`, `[music_end]`, `[end]` and the `BEAT` track carries one quarter-note marker per beat (pitch 12 downbeat vel 101, pitch 13 vel 100, 480-tick spacing).

Each placeholder track (`build_placeholder_track()` in `midi_generator.py`) emits one note per difficulty using `PLACEHOLDER_DIFFICULTY_PITCHES = (60, 72, 84, 96)` — EasyStart=60, MediumStart=72, HardStart=84, ExpertStart=96, matching the difficulty start keys in LibForge's `RBMidConverter.cs`. This is mandatory: `RBMidConverter` (`HandleDrumTrk` / `HandleGuitarBass`) stores `gem_tracks` as a 4-element difficulty array (Easy/Medium/Hard/Expert) that is filled lazily only when a note for that difficulty is seen, then runs `gem_tracks.Select(g => g.ToArray()).ToArray()` (RBMidConverter.cs:606 and :975). A single note at pitch 60 filled only the Easy slot, leaving Medium/Hard/Expert null and throwing `System.NullReferenceException` during ForgeTool "CON to PKG Conversion" (fixed in v0.0057).

## LRC Lines as the Phrase Source of Truth (highest-priority roadmap item)
Rock Band phrases are 2-bar (or 4-bar) windows on the beat grid, but the *natural* phrase boundaries come from the song's lyric lines. Design decision: each line of the user's `.lrc` file should define one vocal phrase (open the phrase at the first word of the line, close at the last word's end), with measure-based windows as the fallback only when the `.lrc` is missing or doesn't make phrasing obvious. This keeps phrasing musical (verse lines, chorus lines) instead of rigid fixed windows. **Current limitation:** phrase boundaries fall back to fixed 2-bar measure windows, so in-game phrase regions and vocal scoring feel wrong — each `.lrc` line timestamp marks the start of one vocal phrase and should be the source of truth.

## WhisperX Small-Word Misplacement (known weakness)
WhisperX forced alignment occasionally lands a short word (e.g. "I", "a", "the") at the end of the *previous* phrase instead of the start of the *next* one, because its alignment cost favors the nearer vowel. When LRC lines drive phrasing, words need **re-anchoring to their LRC line**: if a word's aligned position falls outside its LRC line's time span, snap it to the line boundary (start of its own line, or end of the previous line) rather than trusting the raw alignment.

## Vocal Key Detection (v0.0063) & Freestyle Gating (v0.0067)
`autorb/export/key_detect.py` runs Krumhansl-Schmuckler key-finding on the Basic-Pitch `note_events` (pitch classes weighted by note duration, rotated key profiles compared by cosine similarity) and returns `(tonic_pitch_class, tonality)` — 0-11 chromatic (0=C) and 0=major/1=minor. These feed `(vocal_tonic_note N)` and `(song_tonality 0|1)` in `songs.dta`. Eve 6's "Open Road Song" detects as A major (tonic 9, tonality 0). **Correction (v0.0067):** these dta fields are *not* what enables RB4's "Acceptable Pitch" guide lanes — they have no slot in the PS4 `songdta_ps4` binary and are dropped by `SongDataConverter`. On PS4 the guide lanes are gated by `HasFreestyleVocals` in `songdta_ps4` (written by `SongDataWriter.cs:42`); the game computes the guide scale from charted vocal notes per Harmonix patent US 2010/0304810 once the feature is enabled. AutoRB's `--generate-freestyle-vocals` flag writes `(freestyle_vocals 1)` into `songs.dta`, which the patched vendored ForgeTool reads into `HasFreestyleVocals`. See `rock_band_customs_domain.md`.

## Mandatory Count-In (v0.0064)
Rock Band charts are not allowed to start musical content at tick 0. Stock RB3 DLC bakes a silent lead-in into the MOGG audio (311 - Down has ~5s of silence before its first note, with `[music_start]` at tick 5280), and the game/gamertag/lyrics all assume that pre-roll exists. AutoRB now reproduces it:
- `mogg_builder.build_mogg_from_stems(..., count_in_ms)` prepends silence to all 10 channels via ffmpeg `adelay={count_in_ms}:all=1`.
- `midi_generator.count_in_params(beat_times)` sizes it from the song's opening beat-grid tempo: **3 measures (12 beats)** per the C3 authoring guide's >=160 BPM rule. Eve 6's "Open Road Song" (161.5 BPM opening) → 4458 ms / 5760 ticks.
- `generate_vocal_midi(..., count_in_ticks)` shifts every chart event (vocal notes, phrase markers, `EVENTS`, `BEAT`, tempo map) past the count-in. `[prc_intro]`/`[music_start]` land at `count_in_ticks` instead of tick 0.
- `--skip-mogg` reuses an existing `.mogg` (which was already built WITH this count-in lead-in baked in), so the count-in is still computed from the cached beat grid and the chart is still shifted past it — keeping the rebuilt chart and reused audio in sync. `count_in == 0` only when there is no usable beat grid (v0.0073: it is no longer forced to 0 under `--skip-mogg`).

### Why the first phrase underflow broke the vocal guide
ForgeTool's `RBMidConverter.cs:1286` computes phrase start times as `e.StartTicks - 640` on a `uint`. When a chart's first phrase marker sat at tick 311 (our pre-0.0064 charts started content at tick 0), `311 - 640` wrapped to `4294966967`; `GetMillis` then returned end-of-song (~198s), so the first phrase's StartMillis landed at the end with a negative length (`RBMidWriter.cs:197` writes StartMillis/LengthMillis verbatim). The fix is structural, not a constant `+640` shift (which is impossible anyway: `MidiHelper.cs:23-31` does `idx--` on the tempo map and crashes with index -1 if tick 0 has no tempo entry). Moving the first phrase to tick 6071 makes `6071 - 640 = 5431` safe.
