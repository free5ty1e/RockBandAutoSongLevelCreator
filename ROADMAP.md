# AutoRB Feature Roadmap

## Completed Features
- [x] **Universal Audio Ingestion:** CLI support for standard audio formats (MP3, WAV, FLAC, M4A) via FFmpeg.
- [x] **AI Stem Separation:** Integration with Meta's **Demucs** to isolate drums, bass, vocals, and backing tracks.
- [x] **Smart Lyrics & Vocal Alignment:** Enhanced LRC (.lrc) parsing and WhisperX forced alignment.
- [x] **Automatic Instrument Transcription:** Spotify's **Basic-Pitch** and signal processing for 5-lane instrument tracks.
- [x] **MOGG Audio Container Builder:** Multi-channel OGG mixing with Harmonix container format support (`--skip-mogg` CLI flag).
- [x] **C3/Magma Compatible DTA Writer:** Automated `songs.dta` metadata generation formatted with single-quoted keys and track mappings.
- [x] **Automatic Difficulty Rating Calculator:** Per-instrument `rank` values computed from chart note density via level bands 1-6 (`difficulty.py`, v0.0061): each instrument maps its notes/sec to a difficulty level calibrated against the "311 - Down" DLC reference (drum 30.2 nps → level 5, guitar 18.9 → 4, bass 9.9 → 3, vocals 3.35 → 2) and emits that level band's midpoint rank; `band` = hardest charted instrument. Our chart now reports vocals 159 / band 188 (2 of 6) instead of the hardcoded `(rank ... 150 ...)` block that rendered every song as difficulty 1 of 6.
- [x] **Custom Album Art Support:** New `--album-art` CLI flag encodes any PNG/JPG cover into the CON's `_keep.png_xbox` texture (reverse-engineered HMXBitmap header + byte-swapped DXT1/DXT5, matching SuperFreq `png2tex --platform x360` output); defaults to a generated "Chris Prime Custom" image (v2: stacked CHRIS/PRIME on two lines with an orange "BOT" badge in the top-right corner).
- [x] **Devcontainer Test Suite:** Comprehensive PyTest test suite (`tests/test_con.py`, `tests/test_texture_and_difficulty.py`) running locally in the devcontainer.

## In Progress
- [~] **In-Game Audio Playback:** The STFS/CON package now validates and loads in ForgeTool (`STFS VALID`, `forge SUCCESS`). The tested PKG on PS4 (RB4DX) was built from stale v0.0061 artifacts: its chart closed every vocal phrase with `note_on 105 vel 0` (no `note_off`), so all 284 notes sat outside any phrase and nothing scored. Current code already emits proper `note_off` (regenerated chart: 59 opens == 59 closes), and a fresh rebuild restores vocal scoring (confirmed working on the user's retest: phrases recognized, score bar fills). **Progressive lyric drift** was fixed in v0.0063 by writing a real dynamic tempo map (one `set_tempo` per beat interval, derived from `tempo_map.json`, anchored so tick 0 == audio 0) instead of one averaged BPM — word ticks now round-trip within 1.3 ms across the whole song. Remaining on PS4: **no audio preview in song list** and **no count-in** (song starts immediately with a crowd boo). Count-in is audio-based per C3/RBN docs — prepend a 2-measure "one-two, one-two-three-four" click at the first bars' tempo to the MOGG; `[music_start]` (currently tick 0) then fires the crowd cheer after the click.

## Instrument Transcription Accuracy (post-v0.0.98)

v0.0.98 made charts *representative* (chords via `detect_chord_tones`, density
restored by dropping the `conf>0.5` gate, simultaneous notes fixed in the MIDI
writer). The first PS4/Clone Hero playtest confirmed the pipeline now attempts
to represent each track, but flagged articulation/accuracy gaps. These are the
tracked follow-ups (detailed plans in `.ai_memory/plans/`):

- [ ] **Guitar rapid re-strums collapse into one note (intro especially).** Onset `wait=5` (~58 ms) suppresses the 2nd attack and `detect_holds` over-extends the first note across the gap. Fix: lower `wait` + re-attack splitter + cap every hold to the next same-lane onset. Plan: `instrument_transcription_accuracy.md` + `guitar_bass_articulation_fixes.md`.
- [ ] **Bass separate notes merge into one super-long hold.** `detect_holds_bass` extends a sustain while RMS ≥ 25% (up to 8 s) with **no cap to the next onset**, and the `conf > 0.4` onset gate drops legitimate attacks. Fix: cap hold to next onset, raise RMS threshold, lower/remove the onset conf gate, add min inter-note gap. Plan: `guitar_bass_articulation_fixes.md`.
- [ ] **Drums have no usable Hard/Medium/Easy.** `create_all_difficulties` only thins by density caps (6–16 nps); drum density (~2.9 nps) is below every cap, so Hard/Med/Easy == Expert — unusable for the user's PS4 kit. Fix: grid/role-based drum reduction (kick/snare/hat groove per difficulty, toms/cymbals only on stronger difficulties). Plan: `drum_difficulty_derivation.md`.
- [ ] **Cross-cutting accuracy + validation harness.** Pitch/fret correctness, strum-vs-HOPO derivation, beat-grid quantization of notes, and a chart-quality gate (per-difficulty note/chord counts, on-grid %, distinct lower difficulties) so un-playtested charts stop shipping. Plan: `instrument_transcription_accuracy.md`.

## Planned Features & Enhancements
- [ ] **Dummy test input data for CI-runnable pipeline tests:** The data-dependent integration/quality tests (`test_midi_lyrics_vs_lrc_integration.py`, `test_quality_validation.py`, `test_vocal_sync_fixes.py::test_every_word_start_snaps_to_real_onset`, `test_lyrics_parity.py`) currently `pytest.skip` on a fresh checkout because they read real pipeline artifacts (`output_fixed/`, `output/`, `output_fresh/`). Provide small checked-in fixture files (a short synthetic synced-track JSON + LRC that exercises the assertions) so these strict checks actually RUN in CI instead of skipping — while keeping the real-artifact path as an opt-in `AUTORB_OUTPUT_DIR`/env override for devcontainer runs. (Note: some of these tests fail against the *current* chart output — they encode the open sync issues, so the dummy fixtures must be chosen to keep them meaningful, e.g. fixtures that pass or fail in the same way the real data does.)
- [ ] **Clone Hero chart-file preference & playtest verification:** Confirm empirically which file CH loads when a folder contains **both** `notes.chart` and `notes.mid` (the v0.0.91 BPM-integer fix makes the `.chart` loadable, but its tempo is integer-quantized to ~35ms while `notes.mid` is exact — if CH prefers the `.chart`, the playtest is quantized; if it prefers the `.mid`, it's exact). Also confirm on the user's machine that the Open Road Song export now appears in the song list (Settings → General → Scan Songs, then check `badsongs.txt` if not).
- [ ] **LRC-Line Phrase Source of Truth (highest priority):** Each timestamped line in the user's `.lrc` file marks the **start of one vocal phrase** — open the phrase at the first word of the line and close at the last word's end. Currently phrase boundaries fall back to fixed 2-bar measure windows on the beat grid, which makes the in-game phrase regions and vocal scoring feel all wrong. Re-anchor small words that WhisperX misplaces to their LRC line's time span. **The 2-bar measure-window fallback remains** for when the `.lrc` file is missing or doesn't make phrasing obvious.
- [ ] **Lyric/Audio Sync Improvements:** Tighten the remaining early/late per-word outliers so each lyric lands exactly on the sung audio (onset-snapped timing fixed the progressive drift; per-word jitter remains).
- [ ] **Detect & Fill Missing Lyrics:** Scan the vocal stem for sung regions that are *not* represented by any charted note (e.g. the ad-lib "YEAHHHHH!" after the "forgotten" sustain in "Open Road Song"), transcribe them with WhisperX where possible, and emit pitched Rock Band vocal notes for them so nothing the singer actually sings is left uncharted. Treat the `.lrc` as a *suggestion*, the audio as the source of truth. Detailed plan: `.ai_memory/plans/missing_lyrics_detection_and_filling.md`.
- [ ] **One Pitch per Lyrical Syllable (lyrical resolution enhancement):** Every syllable gets its own note/pitch instead of one static pitch per word.
- [ ] **Vocal Pitch Tracking:** When the singer changes pitch while singing a single lyric, the on-screen note moves up/down with the voice (sliding pitch transitions) rather than a single flat pitch per word.
- [ ] **Overdrive Section Marking:** Automatically mark overdrive activation phrases (and vocal fills / talkie sections) so players can activate overdrive.
- [ ] **Solo / Harmony 1 / Harmony 2 Detection, Separation & Instrument Tracks:** Split the vocal stem into melody + harmony parts, detect solo sections, and build real (non-placeholder) drum/guitar/bass charts.
- [ ] **Syllable-Level Pitch Mapping:** Support multi-pitch contours per word by mapping individual syllables and sliding pitch transitions rather than a single static pitch per word segment.
- [ ] **Keys (Keyboard) Support:** The Demucs "other" stem mixes guitar + keys together. Implement PART KEYS transcription by either: (a) reusing the guitar transcription from the "other" stem but mapping to the 2-octave keys lane layout (Rock Band keys highway), or (b) adding a proper G2P-based separation of guitar vs. keyboard content in the mixed stem. Keys lanes in Rock Band are a 2-octave piano roll (MIDI pitches 24–84 typically), not the 5-lane guitar mapping. Add `keys.py` transcription module and `PART KEYS` track generation.
- [ ] **Dynamic Syllable Segmentation (replace hardcoded dictionary):** Replace the manual `_MANUAL_SYLLABLES` fallback with a scalable approach — combine CMUdict pronunciation dictionary + pyphen + WhisperX character timing + optional G2P (grapheme-to-phoneme) model for unknown words. Syllabification should be derived from pronunciation, not orthography, and pitch tracking should only emit multiple MIDI notes per syllable when the singer actually changes pitch (detected via pyin contour).
- [ ] **Pause/Resume Freeze on PS4 (Known Bug):** When pausing and resuming a custom song on RB4DX, the game freezes. Likely related to MOGG seekability — the container may not have proper Ogg page headers/seek tables for random access, or the preview/song data layout prevents mid-song seeking. This may share root cause with the silent song-list preview (both involve MOGG structure). Investigate Ogg page structure, seek table completeness, and compare against stock DLC MOGG byte-for-byte.
- [ ] **Robust Tempo Detection with Stem Fallback Chain (drums → bass → vocals → other):** Beat tracking currently runs on the **drums** stem (percussive transients via `librosa.onset`/`librosa.beat`) and only falls back to the **vocals** stem to fill drumless sections (`autorb/audio/tempo.py` `_merge_beat_sequences`). Songs whose drums stem is silent, all-break (intros/outros/bridges with no kit), or instrumentals without vocals currently get a wrong or missing tempo map. Add a **fallback chain that picks the best stem for tempo analysis in the order drums → bass → vocals → other**: after beat-tracking a stem, validate the result (e.g. beat count, onset-envelope strength, median inter-beat-interval sanity vs. the 60–200 BPM window, gap density) and if it fails validation try the next stem in the chain; merge across stems per-section (e.g. bass drives the intro until drums kick in) instead of a single whole-song choice. `other` is the last resort because it mixes guitars/keys/backing and its onsets are the least beat-coherent. Also surface *which* stem(s) drove each section in `tempo_map.json` so the beat grid is auditable.
- [ ] **Vocal Gender Detection:** Automatically analyze the pitch and spectral characteristics of the dominant vocal stem to infer singer vocal gender (`'male'` vs `'female'`) for `songs.dta` metadata.
- [ ] **Tambourine Detection & Mapping:** Automatically detect vocal-free sections (e.g., long instrumental breaks) to map them as "Tambourine" sections in the vocal track, enabling users to tap the microphone as a tambourine instrument.
- [ ] **Multi-Harmony Vocal Extraction:** Extract harmony parts and melody parts from vocal tracks to support Rock Band's multi-harmony system (up to 3 microphones: 1 melody and 2 harmonies).
- [ ] **Master Track Multitrack Support:** Allow passing separated master guitar and keyboard audio parts directly when original multitracks/stems are available, bypassing AI Demucs separation.
- [ ] **Solo Section Recognition:** Automatically detect and mark guitar, drum, and bass solo sections to activate the Rock Band solo scoring/lighting system.
- [ ] **Overdrive & Drum/Vocal Fill Markers:** Automatically compute and mark overdrive (star power) activation phrases across instruments, including vocal overdrive sections and regular activation opportunities / talkie/freestyle phrases during lyrical breaks.
- [x] **Clone Hero Song Export (`--build-clone-hero`):** Add a CLI flag that also builds/outputs a Clone Hero-format song (`.chart` or `.mid` + audio) alongside the Rock Band CON — Clone Hero (https://clonehero.info/) is a free, fan-made Guitar Hero-style rhythm game that plays custom songs in a directory-based folder structure, so the chart can reuse the same generated instrument notes, vocal/keyboard lanes, and separated audio mix without the Xbox 360 STFS/CON packaging or count-in required by Rock Band. **Shipped in v0.0.89** (`autorb/export/clone_hero.py` + `autorb/audio/preview.py` + `autorb/export/alignment_report.py` for the no-PS4 sync validation loop; see `llm-wiki-kb/local_preview_and_testing.md`).
